# 10 双层世界观生成器

> 状态：第一版已实现  
> 日期：2026-08-03  
> 适用范围：新游戏世界选择、角色创建之前的世界简报生成  
> 关联文档：[初始化流程](../07_initialization_flow/README.md)

---

## 1. 决策摘要

世界观生成器采用同一份底层配置的两种视图：

- **快速生成**：面向希望尽快开始的用户，提供常见预设和三个直观问题。
- **详细定制**：面向希望控制世界细节的用户，展开快速选择背后的原子参数。

两种模式不是两套生成器。切换模式不得重置、丢失或偷偷改写任何已选内容。

世界创建只描述世界，不描述玩家角色。玩家性别、姓名、年龄、身份、背景和属性仍在下一阶段独立设置，完整世界在角色确认后生成。

创建界面不展示“世界秘密”“特殊规则”“故事结构”“核心冲突”或“叙事阶段”。用户只配置角色理应知道的世界常识与内容边界；未知真相由生成器在后台产生，并按信息层级逐步揭示。

---

## 2. 背景与问题

当前世界选择以扁平预设为主。继续增加“小镇日常”“哥特恐怖”“太空歌剧”等预设会产生以下问题：

1. 预设数量不断增长，但用户仍然难以组合自己真正想玩的世界。
2. 世界类型、故事主题、舞台和氛围混在同一个名称中，用户不知道能修改哪一部分。
3. 创意过强的预设会提高理解成本；“蒸汽剑宗”一类组合适合作为生成结果，不适合作为一级入口。
4. 如果世界预设同时携带主角原型，AI 会在玩家明确选择角色之前推断性别、职业和过去。
5. 将“时间循环”“神明真实存在”等特殊规则直接展示，会把本应在游玩中发现的内容变成剧透。
6. 将“核心冲突”视为所有世界的必备项，会把日常、关系和生活类故事强行转化为危机叙事。

本设计用“常见预设 + 快速组合 + 详细原子参数”解决入口简单性和组合深度之间的矛盾。

---

## 3. 目标与非目标

### 3.1 目标

- 新用户可以点击一个常见预设后直接进入人物创建。
- 不使用预设时，用户通过三个问题完成快速世界选择。
- 详细用户可以修改文明、舞台、社会、技术和超自然边界。
- 点击预设后可以只修改其中一个因素，不必从头创建。
- 快速和详细模式共享同一状态，来回切换结果不变。
- 世界摘要即时更新，不需要提前调用 LLM。
- 所有用户明确选择都成为生成时的权威约束。
- 日常、人际和成长是与悬疑、冒险、生存同级的主题。
- 预设只包含常见、可预期的世界方向，不包含具体剧情和角色身份。
- 隐藏世界秘密不出现在创建界面、公开世界摘要或开场剧透中。

### 3.2 非目标

- 不在这一阶段创建玩家角色。
- 不允许用户手工编排叙事阶段、事件链或结局。
- 不要求用户填写所有详细字段；`自动` 是合法且重要的状态。
- 不在 V1 提供世界图片生成。
- 不在 V1 提供多人共同编辑世界。
- 不在 V1 提供社区预设市场。
- 不保证每个世界都存在超自然秘密、反派、阴谋或最终危机。

## 4. 体验原则

### 4.1 简单是默认路径

首次进入始终显示快速模式。用户不需要理解“文明阶段”“社会形态”等概念才能开始。

### 4.2 详细是渐进展开，不是专家表单

详细模式在同一工作台内展开参数。世界摘要和主要操作始终可见，避免进入另一个长表单页面。

### 4.3 预设是常见答案

预设用于回答“多数人通常想玩什么”，不是用于证明系统可以生成多奇特的组合。罕见组合由用户在详细模式中修改普通预设得到。

### 4.4 用户选择世界常识，系统保留未知

世界类型、舞台、技术水平和超自然是否公开属于可配置常识。具体异常、秘密历史和隐藏因果属于生成器私有层。

### 4.5 不将主题等同于冲突

- 日常主题可以围绕工作、料理、节庆、邻里和兴趣自然推进。
- 悬疑主题可以调查一件旧物或地方传闻，不必升级成阴谋。
- 冒险主题可以是旅行、见闻和结识同伴，不必出现敌人。
- 人际主题可以由不同愿望、误解和生活变化推进，不必设置反派。

### 4.6 组合优先于兼容性禁令

详细模式允许非典型组合。系统可以提示“这是少见组合”，但原则上不禁用选项。用户选择“工业技术 × 武侠传统”时，生成器应将其解释为合理的架空世界，而不是报错。

---

## 5. 信息架构

世界创建位于完整新游戏流程的第一阶段：

```text
世界创建
  ├─ 快速生成
  │    ├─ 常见预设
  │    ├─ 世界类型
  │    ├─ 故事主题
  │    └─ 故事氛围
  ├─ 详细定制
  │    ├─ 文明与世界传统
  │    ├─ 主要舞台
  │    ├─ 社会形态
  │    ├─ 技术水平
  │    ├─ 超自然边界
  │    ├─ 故事主题与氛围
  │    └─ 补充与排除
  └─ 实时世界摘要
       ↓
人物身份（性别必选，其他可选）
       ↓
人物属性
       ↓
确认世界与人物
       ↓
LLM 生成完整世界
```

“快速生成 / 详细定制”是界面状态，不是两种协议或两份存档格式。

## 6. 快速生成模式

### 6.1 常见预设

预设位于快速模式顶部。点击一次会填写完整底层配置，并立即更新世界摘要。

V1 提供以下十个预设：

| ID | 名称 | 世界组合 | 主题 | 氛围 |
|---|---|---|---|---|
| `modern_city` | 现代都市 | 现代文明、现实传统、大都市 | 人际、成长 | 自动 |
| `campus_youth` | 校园青春 | 现代文明、现实传统、学院 | 人际、成长 | 明快 |
| `cozy_town` | 小镇日常 | 现代文明、现实传统、小镇、社区 | 日常、人际 | 温暖 |
| `urban_mystery` | 都市悬疑 | 现代文明、现实传统、大都市 | 悬疑 | 冷峻 |
| `ancient_life` | 古代生活 | 古典文明、历史传统、城镇、社区 | 日常、人际 | 温暖 |
| `wuxia` | 古代江湖 | 古典文明、武侠传统、门派或旅途 | 冒险、成长 | 自动 |
| `court_politics` | 朝堂权谋 | 古典文明、历史传统、宫廷、帝国 | 权谋、悬疑 | 沉郁 |
| `western_fantasy` | 西方奇幻 | 古典文明、西幻传统、王国或边境 | 冒险、成长 | 自动 |
| `space_scifi` | 太空科幻 | 星际文明、科幻传统、空间站或殖民地 | 冒险、人际 | 冷峻 |
| `post_apocalypse` | 末日废土 | 文明衰退、聚落与荒原 | 生存、冒险 | 苍凉 |

预设约束：

- 名称必须是用户熟悉的类型名称，不使用作品式标题。
- 不包含主角性别、职业、出身或能力倾向。
- 不包含具体开场事件、任务、最终目标和结局。
- 不公开世界秘密和幕后规则。
- 描述只说明公共世界气质，不承诺固定剧情。

### 6.2 三个快速问题

用户不点击预设时，通过以下问题完成选择。

#### 问题一：想进入什么世界？

单选：

- 现代
- 历史古代
- 架空西幻
- 架空武侠
- 未来科幻
- 灾后废土

这些选项是详细参数的宏，而不是新的数据维度。

#### 问题二：想在这里经历什么？

至少选择一个，最多选择两个；第一个是主主题，第二个是副主题：

- 日常生活
- 人际与情感
- 个人成长
- 探索与冒险
- 悬疑与调查
- 生存挑战
- 权谋与政治
- 怪谈与恐怖

主题顺序有意义。`日常 + 悬疑`以生活为主体、疑问为点缀；`悬疑 + 日常`以调查为主体、生活为节奏基础。

#### 问题三：想要什么感觉？

单选，默认 `自动`：

- 自动
- 温暖
- 明快
- 浪漫
- 静谧
- 冷峻
- 沉郁
- 苍凉
- 诡谲

氛围影响语言、色彩和事件表达，不直接等价于冲突强度。

### 6.3 快速模式完成条件

- 已选择世界类型或应用一个预设。
- 已选择至少一个主题。
- 氛围允许保持 `自动`。

满足条件后主按钮为“继续设定人物”，而不是“生成世界”。完整世界必须等角色身份和属性确认后再生成。

## 7. 详细定制模式

所有详细字段都允许选择 `自动`。展开详细模式不是要求补全更多信息，而是提供控制权。

### 7.1 文明阶段

| 值 | 用户文案 | 含义 |
|---|---|---|
| `AUTO` | 自动 | 根据其他条件决定 |
| `CLASSICAL` | 古典文明 | 农业、手工业、传统政治秩序 |
| `INDUSTRIAL` | 工业时代 | 机械化、城市扩张、现代制度萌芽 |
| `MODERN` | 现代文明 | 当代社会结构和技术条件 |
| `NEAR_FUTURE` | 近未来 | 当代社会的技术与制度延伸 |
| `INTERSTELLAR` | 星际文明 | 稳定太空航行与星际聚居 |
| `POST_COLLAPSE` | 文明衰退 | 旧文明遗迹与新的聚落秩序 |

### 7.2 世界传统

“世界传统”描述作品遵循的公共类型语法，不是隐藏规则。

| 值 | 用户文案 |
|---|---|
| `AUTO` | 自动 |
| `REALISTIC` | 写实世界 |
| `HISTORICAL` | 历史古代 |
| `WUXIA` | 架空武侠 |
| `WESTERN_FANTASY` | 西方奇幻 |
| `URBAN_FANTASY` | 都市奇幻 |
| `SCI_FI` | 科幻世界 |

### 7.3 主要舞台

主要舞台决定故事最初的人际密度、空间关系和日常活动，不限制后续旅行。

| 值 | 用户文案 |
|---|---|
| `AUTO` | 自动 |
| `METROPOLIS` | 大都市 |
| `SMALL_TOWN` | 小镇 |
| `ACADEMY` | 学院 |
| `COURT` | 宫廷与权力中心 |
| `SECT` | 门派与组织驻地 |
| `FRONTIER` | 边境与荒野 |
| `JOURNEY` | 旅途 |
| `STATION_COLONY` | 空间站或殖民地 |
| `ISOLATED_SETTLEMENT` | 封闭聚落 |

### 7.4 社会形态

| 值 | 用户文案 |
|---|---|
| `AUTO` | 自动 |
| `EMPIRE` | 帝国与官僚秩序 |
| `CITY_STATES` | 城邦与地方势力 |
| `CLANS` | 宗族与家族网络 |
| `SECTS` | 门派与组织网络 |
| `CORPORATIONS` | 企业与机构社会 |
| `COMMUNITY` | 社区与熟人社会 |
| `DECENTRALIZED` | 无中心的松散秩序 |

社会形态影响 NPC 关系、公共规则和资源流动，不要求生成权力冲突。

### 7.5 技术水平

| 值 | 用户文案 |
|---|---|
| `AUTO` | 自动 |
| `HANDCRAFT` | 传统手工业 |
| `INDUSTRIAL` | 机械与工业技术 |
| `MODERN` | 现代技术 |
| `ADVANCED` | 高度智能化技术 |
| `MIXED` | 混合与遗留技术 |

技术水平可以与世界传统交叉组合。例如 `WUXIA + INDUSTRIAL` 是合法的架空世界，不应被前端禁用。

### 7.6 超自然边界

这一项只定义玩家对超自然内容的接受范围，不揭晓具体特殊规则。

| 值 | 用户文案 | 生成约束 |
|---|---|---|
| `AUTO` | 自动 | 根据世界传统和主题决定 |
| `NONE` | 完全写实 | 不生成真实超自然现象 |
| `RUMORED` | 罕见传闻 | 可以存在，但不应成为人人确认的常识 |
| `PUBLIC` | 公开存在 | 超自然可以进入职业、法律和日常生活 |

禁止在该区域列出“时间循环”“神明消失”“梦境成真”等具体秘密。

### 7.7 主题与氛围

详细模式继续使用快速模式中的主题和氛围状态，不复制一份新值。

### 7.8 补充与排除

提供两个自由文本字段：

- **我还想要**：希望世界包含的公共设定或作者意图，最多 500 字。
- **不要出现**：内容边界与不希望出现的题材，最多 500 字。

“不要出现”优先级高于预设、自动推导和 LLM 创作自由。

## 8. 快速宏与详细参数映射

快速世界类型应用以下默认参数：

| 快速类型 | 文明阶段 | 世界传统 | 技术 | 超自然边界 |
|---|---|---|---|---|
| 现代 | `MODERN` | `REALISTIC` | `MODERN` | `AUTO` |
| 历史古代 | `CLASSICAL` | `HISTORICAL` | `HANDCRAFT` | `AUTO` |
| 架空西幻 | `CLASSICAL` | `WESTERN_FANTASY` | `HANDCRAFT` | `PUBLIC` |
| 架空武侠 | `CLASSICAL` | `WUXIA` | `HANDCRAFT` | `RUMORED` |
| 未来科幻 | `NEAR_FUTURE` | `SCI_FI` | `ADVANCED` | `AUTO` |
| 灾后废土 | `POST_COLLAPSE` | `AUTO` | `MIXED` | `AUTO` |

映射规则：

1. 选择快速世界类型会更新上表中的相关详细字段。
2. 主题、氛围、“我还想要”和“不要出现”保持不变。
3. 如果该操作覆盖详细编辑，界面提供一次“撤销”提示，不弹出确认对话框。
4. 单纯切换快速/详细模式绝不修改任何字段。
5. 详细字段偏离宏默认后，快速区域显示“基于「架空武侠」改编”等状态。

## 9. 预设应用规则

点击预设时：

- 覆盖世界类型、所有详细因素、主题和氛围。
- 清空“我还想要”，避免旧要求与新预设相互污染。
- 保留“不要出现”，因为它属于用户内容边界。
- 保存操作前的完整快照，并显示“已应用「小镇日常」· 撤销”。
- 不立即进入下一步，用户仍可查看和修改结果。

修改任意预设字段后：

- 保留来源预设 ID。
- 显示“基于「小镇日常」改编”。
- 不再把当前配置标记为与预设完全一致。

再次点击同一预设会恢复其标准值，并重新提供撤销。

协议和存储必须使用稳定预设 ID，不再依赖数组下标。预设排序变化不得改变旧客户端选择的含义。

## 10. 实时世界摘要

### 10.1 目的

世界摘要承担三个职责：

1. 让用户理解当前选择会生成怎样的公共世界。
2. 让快速和详细模式共享一个稳定的视觉锚点。
3. 在不调用 LLM 的情况下提供即时反馈。

### 10.2 内容

摘要由本地确定性模板生成，包括：

- 一行世界公式，例如 `架空武侠 · 小镇 · 日常 / 人际 · 温暖`。
- 一至两句自然语言概述。
- 当前预设状态，例如 `小镇日常` 或 `基于「小镇日常」改编`。

示例：

> 一个以日常生活和人际关系为中心、气氛温暖的架空武侠小镇。世界会优先描写熟人关系、工作、节庆和生活变化，不会默认制造重大阴谋。

### 10.3 信息限制

摘要不得包含：

- 隐藏秘密或特殊规则。
- 玩家角色的性别、职业和出身。
- AI 尚未生成的具体 NPC、地点名或事件。
- “你将拯救”“你必须调查”等强制任务语言。

### 10.4 国际化

摘要不应通过拼接中文短语实现。每种语言提供完整句式模板，并将选项作为插值参数传入。

```text
└────────────────────────────┘
```

移动端详细参数使用分段展开，但当前选择摘要始终可见。底部主操作保持在安全区域内。

### 11.3 键盘与焦点

- 模式切换使用可访问的 tab/segmented-control 语义。
- 每组单选使用 `radiogroup`，主题多选使用带 `aria-pressed` 的按钮或复选语义。
- 点击预设后焦点不跳到页面顶部。
- 展开详细模式后，焦点移动到首个详细分组标题。
- 主按钮禁用时必须提供可读原因，而不只依赖透明度。

### 11.4 撤销

以下操作提供单步撤销：

- 应用预设。
- 切换快速世界类型并覆盖详细值。
- 重置为自动。

切换视图不需要撤销，因为它不改变数据。

## 12. 视觉与动效方向

### 12.1 视觉命题

界面像一册正在编写、尚未装订的世界志：克制的深色纸面、明确的文字层级、少量铜色强调，世界摘要是唯一主要视觉焦点。

### 12.2 内容计划

- **定位**：步骤进度与模式切换。
- **支持**：常见预设，负责快速开始。
- **工作区**：因素选择或详细参数。
- **视觉锚点**：实时世界扉页，负责解释当前结果。
- **最终操作**：继续设定人物。

### 12.3 动效命题

V1 使用三类必要动效：

1. 点击预设后，各因素以 40–70ms 间隔依次落位，让用户理解预设由什么构成。
2. 快速/详细切换使用共享布局过渡，世界扉页保持原位，选择区展开或收拢。
3. 单个因素改变时，世界公式中的对应词语短距离替换，不让整张界面重新淡入。

动效需支持 `prefers-reduced-motion`；降级后直接更新，不影响功能。

### 12.4 明确避免

- 不使用预设卡片墙。
- 不为每个选项添加装饰性图标。
- 不同时使用多种强调色表示主题。
- 不使用与内容无关的渐变和粒子背景。
- 不让世界扉页变成营销式大标题。
- 不在详细模式堆叠十几个有边框的面板。

## 14. 自动解析与叙事指导

### 14.1 `AUTO` 解析优先级

从高到低：

1. 用户明确选择。
2. 用户应用的预设值。
3. 快速世界类型宏。
4. 主主题和副主题的默认映射。
5. 固定产品默认值。

同一层级冲突时，“不要出现”优先。

### 14.2 产品默认解析表

Resolver 按以下确定性规则补全剩余 `AUTO`。前面的用户值、预设值和快速宏值不会被这些默认覆盖。

#### 文明阶段

| 世界传统 | 默认文明阶段 |
|---|---|
| 写实世界 | `MODERN` |
| 历史古代 | `CLASSICAL` |
| 架空武侠 | `CLASSICAL` |
| 西方奇幻 | `CLASSICAL` |
| 都市奇幻 | `MODERN` |
| 科幻世界 | `NEAR_FUTURE` |

如果世界传统也为 `AUTO`，文明阶段最终回退为 `MODERN`。

#### 世界传统

| 文明阶段 | 默认世界传统 |
|---|---|
| 古典文明 | `HISTORICAL` |
| 工业时代 | `REALISTIC` |
| 现代文明 | `REALISTIC` |
| 近未来 | `SCI_FI` |
| 星际文明 | `SCI_FI` |
| 文明衰退 | `REALISTIC` |

#### 主要舞台

| 条件 | 默认主要舞台 |
|---|---|
| 星际文明 | `STATION_COLONY` |
| 文明衰退 | `ISOLATED_SETTLEMENT` |
| 武侠传统 | `JOURNEY` |
| 西方奇幻 | `FRONTIER` |
| 现代、近未来或都市奇幻 | `METROPOLIS` |
| 其他 | `SMALL_TOWN` |

#### 社会形态

| 主要舞台 | 默认社会形态 |
|---|---|
| 宫廷与权力中心 | `EMPIRE` |
| 门派与组织驻地 | `SECTS` |
| 小镇、学院、封闭聚落 | `COMMUNITY` |
| 大都市、空间站或殖民地 | `CORPORATIONS` |
| 边境、旅途 | `DECENTRALIZED` |

无法匹配时回退为 `COMMUNITY`。这是社会组织的生成起点，不意味着企业、帝国或社区必然成为冲突来源。

#### 技术水平

| 文明阶段 | 默认技术水平 |
|---|---|
| 古典文明 | `HANDCRAFT` |
| 工业时代 | `INDUSTRIAL` |
| 现代文明 | `MODERN` |
| 近未来、星际文明 | `ADVANCED` |
| 文明衰退 | `MIXED` |

#### 超自然边界

| 条件 | 默认边界 |
|---|---|
| 西方奇幻 | `PUBLIC` |
| 武侠或都市奇幻 | `RUMORED` |
| 主主题或副主题为怪谈 | `RUMORED` |
| 其他 | `NONE` |

#### 氛围

| 主主题 | 默认氛围 |
|---|---|
| 日常、人际 | `WARM` |
| 成长、冒险 | `BRIGHT` |
| 悬疑 | `COLD` |
| 生存 | `DESOLATE` |
| 权谋 | `SOMBER` |
| 怪谈 | `UNCANNY` |

解析结果必须可重复：相同 Draft 在相同 Schema 版本下始终得到相同 ResolvedWorldBrief，不调用随机数或 LLM。

### 14.3 主题到内部指导的默认映射

内部指导不显示在创建界面。

| 主主题 | 默认模式 | 默认压力 | 主要事件来源 |
|---|---|---|---|
| 日常 | `OPEN` | `CALM` | 日程、工作、兴趣、节庆、社区变化 |
| 人际 | `SUPPORTIVE` | `GENTLE` | 关系、承诺、误解、共同活动 |
| 成长 | `SUPPORTIVE` | `GENTLE` | 学习、尝试、选择、能力与身份变化 |
| 冒险 | `DIRECTED` | `ACTIVE` | 旅行、发现、环境变化、相遇 |
| 悬疑 | `DIRECTED` | `ACTIVE` | 疑问、线索、调查、不同解释 |
| 生存 | `DIRECTED` | `INTENSE` | 资源、环境、安全、聚落稳定性 |
| 权谋 | `DIRECTED` | `ACTIVE` | 制度、利益、联盟、公开与私下立场 |
| 怪谈 | `SUPPORTIVE` | `GENTLE` | 传闻、禁忌、异常痕迹、地方记忆 |

这是基准，不是硬编码剧情模板。副主题、氛围、预设覆盖和内容排除可以调整最终指导。

### 14.4 氛围不等于压力

“温暖”不能简单转换为 `CALM`，“冷峻”也不能简单转换为 `INTENSE`。氛围首先控制叙述语言、感官细节和后果表达；压力主要由主题和预设决定。

## 15. 世界秘密与信息层级

世界秘密由完整世界生成阶段创建，不属于 `WorldCreationDraft`。

### 15.1 生成约束

- 世界秘密必须遵守超自然边界和“不要出现”。
- 世界秘密不得改写用户明确选择的公共常识。
- 世界秘密一旦写入 Genesis 文档即成为权威事实，后续不得临时反转。
- 秘密应在普通生活、制度或地点中留下可观察后果，而不是只有一句幕后说明。
- 开场只允许展示可感知后果，不直接解释秘密。
- 日常与写实世界允许没有宏大秘密；系统不得为了“精彩”强制加入反转。
- 悬疑和怪谈主题可以提高秘密密度，但秘密仍不等于反派阴谋。

### 15.2 信息分层

```text
玩家可知
  ├─ ResolvedWorldBrief 中的公共世界常识
  ├─ 玩家角色自己知道的背景
  └─ 开场现场可以直接感知的信息

可发现但未知
  ├─ 地方历史的缺口
  ├─ NPC 未公开的关系与动机
  └─ 异常现象背后的规律

仅 GM 可知
  ├─ hidden_secrets
  ├─ NPC deep_motivation
  └─ 尚未被发现的因果联系
```

创建界面的世界扉页只能使用第一层。

## 16. 初始化与生成流程

目标流程：

```text
1. 服务端发送世界选项目录与常见预设
2. 用户在快速或详细模式编辑 WorldCreationDraft
3. 客户端本地生成实时摘要
4. 用户点击“继续设定人物”
5. 代码校验并解析为 ResolvedWorldBrief
6. 用户选择二元性别并填写可选人物信息
7. 用户分配属性并确认
8. WorldGenerator 接收：
     ResolvedWorldBrief
     + PlayerProfileInput
     + PlayerAttributes
9. LLM 生成 GenesisDocument
10. 代码覆盖并校验所有用户权威字段
11. 保存 GenesisDocument，创建会话并开始游戏
```

在第 8 步之前不得生成完整世界，避免世界生成器提前决定玩家性别和角色身份。

### 16.1 Prompt 合同

WorldGenerator 输入分为三个明确区块：

- **公共世界简报**：已解析的世界因素、主题、氛围和内容要求。
- **玩家角色约束**：性别、姓名、年龄、身份、背景要点和属性限制。
- **私有生成规则**：信息层级、秘密生成、日常题材约束和 Schema。

Prompt 必须要求每个用户选择真实影响至少两个世界方面。例如“公开超自然”不能只出现在背景介绍中，还应影响职业、法律、交通、食物或日常关系。

## 18. 持久化与兼容迁移

### 18.1 Genesis 文档

建议在 `world_setting` 下保存生成时使用的公开简报：

```typescript
world_setting: {
  // existing generated fields
  creation_brief?: ResolvedWorldBrief
}
```

旧存档没有 `creation_brief` 时保持兼容，通过现有 `tone`、`story_drivers` 和 `story_pressure` 读取。

### 18.2 当前 StyleConfig 迁移

当前字段：

```typescript
interface StyleConfig {
  tone: string
  complexity: 'LOW' | 'MEDIUM' | 'HIGH'
  narrative_style: string
  player_archetype: string
  story_drivers: StoryDriver[]
  story_pressure: StoryPressure
}
```

迁移策略：

1. 新 UI 只创建 `WorldCreationDraft`。
2. 新增 Resolver 产生 `ResolvedWorldBrief`。
3. 在过渡期提供 `ResolvedWorldBrief -> StyleConfig` 适配器，复用现有 WorldGenerator。
4. `player_archetype` 固定为空，并在后续版本删除。
5. 当前 `story_drivers` 和 `story_pressure` 改为内部派生值，不再直接展示给用户。
6. 旧 `select_style` / `select_style_custom` 消息保留一个兼容周期，然后删除。

### 18.3 预设迁移

当前预设根据语义映射到新的十个常见预设；不再保留仅靠剧情噱头区分的预设。迁移只影响新游戏入口，不改写已存在的 Genesis 文档和会话。

## 19. 校验与错误处理

### 19.1 Draft 校验

- `schema_version` 必须受支持。
- 主主题必填。
- 副主题不能与主主题相同。
- 自由文本分别不超过 500 字。
- 所有枚举必须来自服务端目录。
- 玩家角色字段不得出现在世界 Draft 中。

### 19.2 解析失败

如果 Resolver 无法解析某个 `AUTO`：

- 使用产品默认值完成解析。
- 记录调试警告。
- 不要求用户理解内部错误。

### 19.3 世界生成失败

- 保留完整 `WorldCreationDraft`、`ResolvedWorldBrief`、人物信息和属性。
- 回到确认阶段并允许重试。
- 不重新随机用户选择。
- 错误信息不得包含 API Key 或完整 Prompt。

## 20. 国际化、可访问性与响应式

### 20.1 国际化

- 枚举 ID 与语言无关。
- 预设名称、说明、选项标签、辅助说明和摘要模板均进入 i18n。
- 中文、英文和日文首发同步提供。
- 不将中文预设名称作为存储值或协议值。

### 20.2 可访问性

- 所有点击项必须是 `button`、`radio` 或 `checkbox` 语义，不用裸 `div`。
- 颜色不能是唯一选中指示；同时使用字重、标记或边线。
- 桌面和移动端触控目标不小于 44px。
- 主流程支持键盘完成。
- 动效支持减少动态效果设置。
- 世界摘要更新使用非打断式 `aria-live="polite"`。

### 20.3 响应式

- 桌面：选择区与世界扉页并列。
- 平板：世界扉页缩窄但保持固定上下文。
- 手机：世界扉页置顶压缩，预设横向滚动，选择区纵向展开，底部主按钮固定。
- 不依赖 hover 才能理解选项说明。

---

## 21. 性能要求

- 世界创建阶段不调用 LLM。
- 摘要生成必须是同步本地计算。
- 选项改变后的可见反馈目标小于 100ms。
- 模式切换不重新挂载整个创建器，不丢失输入焦点和滚动位置。
- 预设目录和选项目录体积保持在静态 JSON 量级。
- 自由文本按需保存到本地 Draft，避免页面误关闭后丢失。

## 22. 测试策略

### 22.1 单元测试

- 每个快速世界类型正确映射详细参数。
- 每个预设产生完整、合法且不包含人物字段的 Draft。
- 应用预设保留“不要出现”、清空“我还想要”。
- 快速/详细模式切换不改变 Draft。
- 修改预设字段后正确显示“基于预设改编”。
- 主题顺序保持稳定，重复主题被拒绝。
- `AUTO` 解析在相同输入下确定性一致。
- 世界摘要不包含未选择的具体地点、NPC 或秘密。
- 内容排除优先于预设和自动推导。

### 22.2 协议测试

- 接受合法 `select_world`。
- 拒绝未知枚举、超长文本和缺失主主题。
- 拒绝世界 Draft 中出现玩家身份字段。
- 旧协议在兼容周期内仍可映射。

### 22.3 Prompt 回归测试

- 二元性别严格遵守玩家选择。
- 世界预设不推断角色性别和职业。
- 日常主题不自动生成反派、阴谋和重大危机。
- `NONE` 超自然边界不生成真实魔法或神迹。
- 世界秘密不出现在公开背景和开场解释中。
- 每个明确世界因素在至少两个生成结果区域产生可观察影响。

## 24. V1 验收标准

满足以下条件才视为功能完成：

1. 用户可以点击任一常见预设后直接继续设定人物。
2. 用户可以不使用预设，通过世界类型、主题和氛围完成快速配置。
3. 详细模式完整展示底层参数，所有字段允许 `自动`。
4. 快速/详细来回切换十次后 Draft 保持完全一致。
5. 修改普通预设可以得到非典型组合，而不会被前端禁止。
6. 预设和 Draft 中不存在玩家性别、职业、出身或能力原型。
7. 创建界面不展示世界秘密和具体特殊规则。
8. 日常主题生成结果不强制核心冲突或最终目标。
9. 二元性别在人物阶段明确选择并覆盖模型输出。
10. Node 服务端和浏览器本地引擎行为一致。
11. 中文、英文、日文界面可完整走通。
12. 单元测试、协议测试、Prompt 回归和前端生产构建通过。

## 25. 后续候选能力

以下能力不进入 V1：

- 锁定部分因素后随机替换其余因素。
- “让我意外”稀有组合模式。
- 同一组因素的多种世界诠释。
- 世界扉页 AI 插图。
- 保存个人预设。
- 分享世界 Draft。
- 从已有 Genesis 文档反推可编辑 Draft。

这些能力必须建立在 V1 的稳定 Draft、Resolver 和预设 ID 之上，不能提前绕过基础模型实现。
